## यह क्या करता है

यह आपके GPU पर [Ollama](https://ollama.com) के माध्यम से स्थानीय रूप से चलने वाले [TranslateGemma](https://ollama.com/library/translategemma) का उपयोग करके 57 भाषाओं के बीच पाठ का अनुवाद करता है। कोई API कुंजी नहीं, कोई क्लाउड नहीं, कोई दर सीमा नहीं — डिफ़ॉल्ट रूप से सब कुछ आपके मशीन पर रहता है। आप [Ollama Cloud](#ollama-cloud-optional) जैसे किसी दूरस्थ Ollama का उपयोग करना चुन सकते हैं।

## त्वरित शुरुआत

### 1. Ollama स्थापित करें

[ollama.com](https://ollama.com) से डाउनलोड करें और इसे शुरू करें:

```bash
ollama serve
```

### 2. एक मॉडल डाउनलोड करें

```bash
ollama pull translategemma:27b   # 17 GB  — the default, highest quality
# or
ollama pull translategemma:12b   # 8.1 GB — faster, for GPUs with less VRAM
# or
ollama pull translategemma:4b    # 3.3 GB — fastest, lower quality
```

> **टिप:** आप इस चरण को छोड़ सकते हैं — पॉलीग्लॉट पहली बार उपयोग करने पर डिफ़ॉल्ट मॉडल (27B, 17 GB) को स्वचालित रूप से डाउनलोड करता है। एक छोटे GPU पर, पहले `POLYGLOT_MODEL=translategemma:12b` सेट करें (देखें [कॉन्फ़िगर करने योग्य डिफ़ॉल्ट मॉडल](#configurable-default-model))।

### 3. अपने MCP क्लाइंट में जोड़ें

**Claude Code / Claude Desktop** — `claude_desktop_config.json` या `.mcp.json` में जोड़ें:

```json
{
  "mcpServers": {
    "polyglot": {
      "command": "npx",
      "args": ["-y", "@mcptoolshop/polyglot-mcp"]
    }
  }
}
```

**स्रोत से:**

```bash
git clone https://github.com/mcp-tool-shop-org/polyglot-mcp.git
cd polyglot-mcp
npm install && npm run build
node dist/index.js
```

बस इतना ही। क्लाउड से कुछ अनुवाद करने के लिए कहें और यह स्वचालित रूप से `translate` टूल का उपयोग करेगा।

## उपकरण

पॉलीग्लॉट छह MCP उपकरण प्रदान करता है:

### `translate`

समर्थित किसी भी भाषा जोड़ी के बीच पाठ का अनुवाद करें।

| पैरामीटर | आवश्यक | विवरण |
|-------------|----------|-------------|
| `text`      | हाँ | अनुवाद करने के लिए पाठ |
| `from`      | हाँ | स्रोत भाषा कोड या नाम (जैसे, `en`, `English`) |
| `to`        | हाँ | लक्ष्य भाषा कोड या नाम (जैसे, `ja`, `Japanese`) |
| `model`     | no       | Ollama मॉडल (डिफ़ॉल्ट: `translategemma:27b`) |
| `glossary`  | no       | कस्टम शब्द प्रतिस्थापन `{"source": "translation"}` के रूप में — अंतर्निहित सॉफ़्टवेयर शब्दावली के साथ मिलाया गया |

लंबे पाठ को स्वचालित रूप से पैराग्राफ और वाक्य सीमाओं पर खंडों में विभाजित किया जाता है, क्रम में अनुवाद किया जाता है, और फिर से जोड़ा जाता है। सभी अनुवादों को गुणवत्ता के लिए मान्य किया जाता है (खाली आउटपुट, इको डिटेक्शन, ट्रंकेशन, गड़बड़ पाठ)।

### `translate_markdown`

संरचना को बनाए रखते हुए पूरे मार्कडाउन दस्तावेज़ का अनुवाद करें। कोड ब्लॉक, HTML तत्व, बैज, URL और तालिका स्वरूपण को बरकरार रखा जाता है — केवल गद्य सामग्री (शीर्षक, पैराग्राफ, टैगलाइन, तालिका कोशिकाएं) का अनुवाद किया जाता है। इनलाइन कोड स्पैन और [सुरक्षित शब्द](#protected-terms-polyglot-termsjson) का अनुवाद करने से पहले प्लेसहोल्डर से बदल दिया जाता है और बाद में पुनर्स्थापित कर दिया जाता है, ताकि कमांड, ध्वज, पैकेज नाम और पहचानकर्ता ठीक वैसे ही वापस आएं जैसे वे लिखे गए थे, और प्रत्येक "N में से M" गिनती `N/M` के रूप में वापस आती है।

| पैरामीटर | आवश्यक | विवरण |
|--------------|----------|-------------|
| `markdown`   | हाँ | अनुवाद करने के लिए पूरी मार्कडाउन सामग्री |
| `from`       | हाँ | स्रोत भाषा कोड या नाम |
| `to`         | हाँ | लक्ष्य भाषा कोड या नाम |
| `model`      | no       | Ollama मॉडल (डिफ़ॉल्ट: `translategemma:27b`) |
| `onLostSpan` | no       | `report` (डिफ़ॉल्ट) अनुवाद से गायब सुरक्षित स्पैन की सूची देता है; `fail` इसे एक त्रुटि बनाता है। [सर्वाइवल चेक](#survival-check---on-lost-span) देखें |

### `list_languages`

अपने कोड के साथ सभी 57 समर्थित भाषाओं को सूचीबद्ध करें।

### `check_status`

जांचें कि Ollama चल रहा है या नहीं और कौन से TranslateGemma मॉडल स्थापित हैं। यदि Ollama नहीं चल रहा है तो यह स्वचालित रूप से शुरू करने का प्रयास करता है।

### `translate_all`

मार्कडाउन सामग्री का एक साथ कई भाषाओं में अनुवाद करें (डिफ़ॉल्ट: 7 — जापानी, चीनी, स्पेनिश, फ्रेंच, हिंदी, इतालवी, पुर्तगाली)। GPU-सुरक्षित सेमाफोर सीमित करने के साथ अनुवादों को एक साथ चलाता है।

| पैरामीटर | आवश्यक | विवरण |
|---------------|----------|-------------|
| `markdown`    | हाँ | अनुवाद करने के लिए पूरी मार्कडाउन सामग्री |
| `from`        | no       | स्रोत भाषा कोड (डिफ़ॉल्ट: `en`) |
| `languages`   | no       | लक्ष्य भाषा कोड की सरणी (डिफ़ॉल्ट: सभी 7) |
| `model`       | no       | Ollama मॉडल (डिफ़ॉल्ट: `translategemma:27b`) |
| `concurrency` | no       | अधिकतम समवर्ती अनुवाद (डिफ़ॉल्ट: 2, अधिकतम: 3) |
| `navBar`      | no       | भाषा नेविगेशन बार इंजेक्ट करें (डिफ़ॉल्ट: सत्य) |
| `onLostSpan`  | no       | `report` (डिफ़ॉल्ट) प्रत्येक भाषा के लिए खोए हुए सुरक्षित स्पैन की सूची देता है; `fail` किसी भी भाषा को त्रुटि में बदल देता है |

### `translate_readme`

README.md **फ़ाइल** का एक ही 7 भाषाओं में अनुवाद करें और `README.<lang>.md` फ़ाइलों को इसके बगल में लिखें, स्रोत README और प्रत्येक अनुवाद में भाषा नेविगेशन बार को ताज़ा करें। प्रति-भाषा स्थिति सारांश (ठीक/विफल, समय, लिखी गई फ़ाइलें) लौटाता है, न कि अनुवादित पाठ; जब आप सामग्री वापस चाहते हैं तो `translate_markdown` का उपयोग करें।

| पैरामीटर | आवश्यक | विवरण |
|---------------|----------|-------------|
| `readmePath`  | हाँ | स्रोत README.md का पूर्ण पथ |
| `tier`        | no       | `quality` (`translategemma:27b`, डिफ़ॉल्ट), `bulk` (`12b`), या `draft` (`2b`); जब `model` सेट होता है तो अनदेखा किया जाता है |
| `model`       | no       | स्पष्ट Ollama मॉडल; `tier` को ओवरराइड करता है |
| `languages`   | no       | लक्ष्य भाषा कोड का सबसेट (डिफ़ॉल्ट: सभी 7) |
| `concurrency` | no       | अधिकतम समवर्ती अनुवाद (डिफ़ॉल्ट: 2, अधिकतम: 3) |
| `navBar`      | no       | भाषा नेविगेशन बार इंजेक्ट करें या ताज़ा करें (डिफ़ॉल्ट: सत्य) |
| `onLostSpan`  | no       | `report` (डिफ़ॉल्ट) प्रत्येक फ़ाइल लिखता है और खोए हुए सुरक्षित स्पैन की सूची देता है; `fail` किसी भी अप्रकाशित भाषा को त्रुटि के रूप में छोड़ देता है |

`translate_readme` README के `.polyglot-terms.json` और `.polyglot-pins.json` को पढ़ता है यदि वे मौजूद हैं।

## विशेषताएं

### स्वचालित रूप से शुरू करें और स्वचालित रूप से डाउनलोड करें
यदि Ollama नहीं चल रहा है तो यह स्वचालित रूप से शुरू हो जाता है। यदि TranslateGemma मॉडल स्थापित नहीं है तो यह स्वचालित रूप से डाउनलोड हो जाता है। कोई मैन्युअल सेटअप आवश्यक नहीं है।

### घातीय बैकऑफ़ के साथ पुनः प्रयास करें
अस्थायी Ollama विफलताओं (नेटवर्क गड़बड़ियाँ, अस्थायी अधिभार) को घातीय बैकऑफ़ (1 सेकंड, 2 सेकंड) के साथ स्वचालित रूप से 2 बार तक पुनः प्रयास किया जाता है। गैर-पुनः प्रयास करने योग्य त्रुटियां (खराब मॉडल नाम, अमान्य इनपुट) तुरंत विफल हो जाती हैं।

### स्मार्ट चंकिंग
लंबे पाठ को प्राकृतिक सीमाओं — पैराग्राफ, फिर वाक्यों पर विभाजित किया जाता है — ताकि अनुवाद संदर्भ को संरक्षित किया जा सके। खंड आकार मॉडल के अनुकूल होते हैं: 2B/4B मॉडल के लिए 2K वर्ण, 12B के लिए 4K, 27B के लिए 6K।

### खंड कैश
अनुवादित खंडों को सामग्री हैश द्वारा कैश किया जाता है (मास्क किए गए स्रोत पाठ + लक्ष्य भाषा + मॉडल का SHA-256, साथ ही खंड में मिलान करने वाले सुरक्षित-शब्द नियमों का एक हैश)। अपरिवर्तित खंड पूरी तरह से पुनः अनुवाद को छोड़ देते हैं, इसलिए संपादन के बाद अनुवाद को फिर से चलाने से केवल वही बदलता है जो बदल गया था। एक सुरक्षित शब्द जोड़ने से उस शब्द को शामिल करने वाले प्रत्येक खंड की कुंजी बदल जाती है, इसलिए एक कैश किए गए अनुवाद को फिर से नहीं चलाया जाता है जिसमें शब्द को फिर से वर्तनी दी गई थी; अन्य खंड अपनी कुंजियाँ रखते हैं। कैश स्रोत फ़ाइल के बगल में `.polyglot-cache.json` में रहता है, जिसमें 30-दिन का TTL होता है। इसका उपयोग `translateMarkdown` लाइब्रेरी API द्वारा तब किया जाता है जब `filePath` दिया जाता है (और रिपॉजिटरी के `scripts/translate-*.mjs` CLI द्वारा); MCP उपकरण इसके बिना अनुवाद करते हैं।

कई रन एक ही कैश फ़ाइल साझा कर सकते हैं। प्रत्येक सहेजने पर, केवल उसी के परिवर्तन को लॉक के तहत फ़ाइल में मर्ज किया जाता है और फ़ाइल को परमाणु रूप से बदल दिया जाता है, ताकि समानांतर में अनुवाद की गई भाषाएँ एक-दूसरे की प्रविष्टियों को बनाए रखें, और किसी एक भाषा के लिए कैश साफ़ करने से अन्य भाषाएँ अप्रभावित रहती हैं।

### अनुवाद स्मृति (फ़ज़ी कैश)
जब सटीक कैश हिट नहीं मिलता है, तो एक कैश किए गए अनुवाद का पुन: उपयोग केवल तभी किया जाता है जब इसका स्रोत केवल व्हाइटस्पेस लेआउट में नए स्रोत से भिन्न हो: किसी पंक्ति के भीतर रिक्ति, किसी भी छोर पर व्हाइटस्पेस, या CRLF बनाम LF। किसी अन्य संपादन को फिर से अनुवाद किया जाता है, जिसमें एक परिवर्तित शब्द, संख्या, विराम चिह्न, अक्षर केस या इनलाइन कोड स्पैन शामिल है। एक कैश किया गया अनुवाद उसके अपने स्रोत का अनुवाद है, इसलिए इसे संपादित पाठ के लिए पुन: उपयोग करने से पुराना पाठ सामने आएगा।

### सुरक्षित शब्द (`.polyglot-terms.json`)
TranslateGemma किसी अन्य लिपि में साधारण पहचानकर्ताओं को फिर से लिखता है: एक हिंदी README ने `XLS-30` को `एक्सएलएस-30` और `Kimi-K3` को `किमी-के3` के रूप में लिखा। यह गणनाओं को भी विकृत करता है: चीनी ने "218/224" को "224/218" में बदल दिया। इसलिए गद्य में पहचानकर्ताओं को इनलाइन कोड स्पैन की तरह मास्क किया जाता है: प्रत्येक को अनुवाद से पहले एक अक्षर-मुक्त प्लेसहोल्डर से बदल दिया जाता है और बाद में पुनर्स्थापित किया जाता है। डिफ़ॉल्ट:

| पैटर्न | मास्क | अपरिवर्तित छोड़ें |
|---------|-------|--------------|
| `url` | `https://…` व्हाइटस्पेस, उद्धरण, ब्रैकेट या बैकटिक तक | |
| `caps-id` | ALL-CAPS टोकन जिसमें एक अंक हो, या `-` या `_` से जुड़े बड़े अक्षर: `XLS-30`, `HOST_REJECTED`, `SHA-256`, `ARM64` | `README`, `API`, `NASA` |
| `camel-case` | CamelCase और mixedCase शब्द: `DepositAuth`, `AMMCreate`, `mixedCase`, `SoulX-Singer` | `URLs`, `IDs`, `GPUs`, साधारण बड़े अक्षरों वाले शब्द |
| `model-id` | एक अक्षर और अंक वाले मॉडल और उत्पाद आईडी: `Kimi-K3`, `gemma4:31b`, `Qwen2.5-32B` | `Node.js`, `top-10` |

गद्य और तालिका कोशिकाओं में "N ऑफ़ M" (`218 of 224`) को एक स्पैन के रूप में मास्क किया जाता है और प्रत्येक भाषा में `218/224` के रूप में पुनर्स्थापित किया जाता है, जो हर जगह सही ढंग से पढ़ता है और इसे उलटा या क्रमसूचक में नहीं बदला जा सकता है। एक तालिका सेल जिसमें केवल एक गिनती है, उसे बिल्कुल भी मॉडल में नहीं भेजा जाता है।

एक रिपॉजिटरी README के बगल में `.polyglot-terms.json` में अपने स्वयं के शब्द जोड़ता है। प्रत्येक फ़ील्ड वैकल्पिक है:

```json
{
  "terms": ["Gemma", "TranslateGemma"],
  "patterns": ["\\bRFC \\d+\\b"],
  "disable": ["camel-case"],
  "nOfM": true
}
```

`terms` सटीक, केस-संवेदनशील स्ट्रिंग हैं जो पूरे शब्दों के रूप में मेल खाती हैं; `patterns` JavaScript नियमित अभिव्यक्तियाँ हैं। दोनों डिफ़ॉल्ट में जोड़ते हैं। `disable` नाम से डिफ़ॉल्ट को बंद कर देता है, और `"nOfM": false` गिनती नियम को बंद कर देता है। एक ऐसी फ़ाइल जिसे पार्स नहीं किया जा सकता है, वह `CONFIG_ERROR` के साथ रन को रोक देती है, बजाय इसके कि वह उन शब्दों के बिना अनुवाद करे जिनकी उसने मांग की थी।

### उत्तरजीविता जाँच (`--on-lost-span`)
अनुवाद के बाद, प्रत्येक लक्ष्य फ़ाइल की अंग्रेजी के साथ जाँच की जाती है: प्रत्येक सुरक्षित स्पैन (इनलाइन कोड स्पैन, सुरक्षित शब्द और प्रत्येक गिनती को `N/M` के रूप में) को उसके खंड के अनुवाद में अक्षर-दर-अक्षर मौजूद होना चाहिए। प्रत्येक तालिका सेल में अपने स्रोत सेल के समान संख्याएँ होनी चाहिए, जिसकी तुलना क्रम में नहीं, बल्कि एक बहुसमुच्चय के रूप में की जाती है: "218/224" के लिए सही चीनी कुल को पहले रखता है (`224 首中的 218 首`), इसलिए एक क्रम जाँच सही उत्तर को चिह्नित करेगी। अन्य लिपियों से अंकों को तुलना करने से पहले सामान्यीकृत किया जाता है। फ़ाइल को अपने संलग्न कोड ब्लॉक और इनलाइन कोड स्पैन को भी बनाए रखना चाहिए।

`--on-lost-span=fail|report` यह चुनता है कि किसी चीज़ के खो जाने पर क्या होता है:

- **`fail`**: रन भाषा, खंड और लापता स्पैन की सूची के साथ गैर-शून्य मान के साथ समाप्त होता है। यह `scripts/translate-all.mjs` के लिए डिफ़ॉल्ट है, जो रिलीज़ से पहले चलता है। फ़ाइलें अभी भी लिखी जाती हैं, इसलिए उन्हें हाथ से ठीक किया जा सकता है और पिन किया जा सकता है। सारांश JSON सूची और सामान्य `PolyglotError` आकार (`code`, `message`, `hint`, `retryable`) में `LOST_SPAN` त्रुटि रखता है।
- **`report`**: सूची लिखी जाती है और रन 0 के साथ समाप्त होता है। यह MCP टूल (`onLostSpan` पैरामीटर) और `translateMarkdown` लाइब्रेरी API (`onLostSpan` विकल्प, परिणाम फ़ील्ड `lostSpans`) के लिए डिफ़ॉल्ट है।

```bash
node scripts/translate-all.mjs README.md                       # --on-lost-span=fail
node scripts/translate-all.mjs README.md --on-lost-span=report
```

### पिन किए गए अनुवाद (`.polyglot-pins.json`)
एक पिन किया गया अनुवाद हमेशा जीतता है। `.polyglot-pins.json` कैश के बगल में बैठता है; प्रत्येक प्रविष्टि को अंग्रेजी खंड के हैश और लक्ष्य भाषा द्वारा कुंजीबद्ध किया जाता है, और इसमें हाथ से ठीक किया गया अनुवाद होता है। एक पिन कैश और मॉडल को हराता है और हर पुन: रन, `--cache-clear` सहित, से बच जाता है। जब अंग्रेजी बदलती है, तो हैश बदल जाता है, इसलिए एक पिन उस पाठ से अधिक समय तक नहीं रह सकता जिसके लिए इसे लिखा गया था।

हाथ से किए गए सुधारों को पिन करने के लिए, अनुवादित फ़ाइल को सही करें, फिर चलाएँ:

```bash
node scripts/pin-translation.mjs README.md hi README.hi.md
```

यह अंग्रेजी के प्रत्येक खंड को सही की गई फ़ाइल में इसके पाठ के साथ जोड़ता है और प्रत्येक खंड को पिन करता है जिसका पाठ कैश किए गए अनुवाद से भिन्न है। `--dry-run` पिन की सूची देता है बिना उन्हें लिखे। `--model=NAME` उस मॉडल को सेट करता है जिसके कैश प्रविष्टियों की तुलना यह करता है (डिफ़ॉल्ट: `$POLYGLOT_MODEL` या `translategemma:27b`, स्क्रिप्ट के समान)। `--include-uncached` उन खंडों को भी पिन करता है जिनके लिए कैश में कोई अनुवाद नहीं है। README के साथ `.polyglot-pins.json` और `.polyglot-terms.json` को कमिट करें।

### ओलामा क्लाउड (वैकल्पिक)
`localhost:11434` के बजाय किसी अन्य ओलामा सर्वर पर अनुरोध भेजने के लिए `OLLAMA_HOST` सेट करें। [ओलामा क्लाउड](https://ollama.com) के लिए, `OLLAMA_API_KEY` भी सेट करें: कुंजी को एक बेयरर टोकन के रूप में भेजा जाता है, और केवल एक गैर-लूपबैक होस्ट पर।

```bash
OLLAMA_HOST=https://ollama.com OLLAMA_API_KEY=... npx @mcptoolshop/polyglot-mcp
```

### समवर्ती सेमाफोर
सीमित VRAM वाले सिस्टम पर GPU OOM को रोकने के लिए सभी ओलामा कॉल को एक गिनती सेमाफोर (डिफ़ॉल्ट सीमा: 1) द्वारा सुरक्षित किया जाता है। `POLYGLOT_CONCURRENCY` के साथ ओवरराइड करें:

```bash
POLYGLOT_CONCURRENCY=2 npx @mcptoolshop/polyglot-mcp
```

### MCP प्रगति टोकन
सभी टूल MCP `notifications/progress` के माध्यम से प्रगति की रिपोर्ट करते हैं जब क्लाइंट `progressToken` प्रदान करता है। अनुवाद प्रति-खंड, अनुवाद_मार्कडाउन प्रति-खंड-बैच, अनुवाद_सभी प्रति-भाषा और जाँच_स्थिति प्रति-चरण की रिपोर्ट करता है।

### सॉफ्टवेयर शब्दावली
12 तकनीकी शब्दों (API, CLI, SDK, आदि) की एक अंतर्निहित शब्दावली सॉफ्टवेयर शब्दावली के सुसंगत अनुवाद को सुनिश्चित करती है। कस्टम शब्दावली प्रविष्टियों को प्रति-अनुरोध पारित किया जा सकता है और डिफ़ॉल्ट के साथ मर्ज किया जाता है।

### बैच अनुवाद
`translateBatch` जहाँ संभव हो, कई खंडों को एक ही प्रॉम्प्ट में समूहित करता है, जिससे राउंड-ट्रिप कम हो जाते हैं। यदि बैच विभाजक को विकृत किया जाता है तो यह व्यक्तिगत अनुवाद पर वापस आ जाता है।

### कॉन्फ़िगर करने योग्य डिफ़ॉल्ट मॉडल
डिफ़ॉल्ट मॉडल `translategemma:27b` है। किसी अन्य का उपयोग करने के लिए `POLYGLOT_MODEL` पर्यावरण चर सेट करें, उदाहरण के लिए कम VRAM वाले GPU पर:

```bash
POLYGLOT_MODEL=translategemma:12b npx @mcptoolshop/polyglot-mcp
```

### संरचित त्रुटियाँ
सभी त्रुटियाँ `PolyglotError` का उपयोग करती हैं जिसमें एक मशीन-पठनीय कोड (`MODEL_NOT_FOUND`, `OLLAMA_UNAVAILABLE`, `TRANSLATION_FAILED`, आदि), एक मानव-पठनीय संदेश, एक वैकल्पिक संकेत और एक `retryable` ध्वज होता है।

### आउटपुट सत्यापन
प्रत्येक अनुवाद को स्वचालित रूप से मान्य किया जाता है: खाली आउटपुट त्रुटि उत्पन्न करता है (पुन: प्रयास किया जा सकता है), स्रोत-पाठ प्रतिध्वनि को चिह्नित किया जाता है, गंभीर संक्षिप्तीकरण और भ्रमित करने वाली त्रुटियों के बारे में चेतावनी दी जाती है, और गलत एन्कोडिंग और मॉडल मेटा-टिप्पणी का पता लगाया जाता है। चेतावनियाँ MCP टूल प्रतिक्रिया में दिखाई देती हैं।

### स्ट्रीमिंग
`OllamaClient.generateStream()`, NDJSON के माध्यम से टोकन उत्पन्न करता है, जैसे कि ओलामा उन्हें उत्पन्न करता है। `translate()` फ़ंक्शन वास्तविक समय की प्रगति प्रदर्शन के लिए एक `onToken` कॉलबैक स्वीकार करता है। स्ट्रीमिंग और गैर-स्ट्रीमिंग दोनों पथों में पुन: प्रयास तर्क साझा किया जाता है।

## सुरक्षा और डेटा दायरा

| पहलू | विवरण |
|--------|--------|
| **Data touched** | ओलामा API को भेजा गया पाठ — डिफ़ॉल्ट रूप से स्थानीय (`localhost:11434`), या यदि आपने एक सेट किया है तो होस्ट `OLLAMA_HOST` में। `.polyglot-cache.json` सेगमेंट कैश एक अनुवादित फ़ाइल के बगल में (केवल लाइब्रेरी और CLI उपयोग)। यदि मौजूद हैं तो `.polyglot-terms.json` और `.polyglot-pins.json` एक अनुवादित README के बगल में पढ़े जाते हैं। |
| **Files written** | `translate_readme`, आपके द्वारा पास किए गए README के बगल में `README.<lang>.md` लिखता है और उस README के भाषा नेविगेशन बार को ताज़ा करता है। `scripts/pin-translation.mjs`, README के बगल में `.polyglot-pins.json` लिखता है। |
| **Data NOT touched** | कोई ब्राउज़र डेटा नहीं, कोई OS क्रेडेंशियल नहीं, उपरोक्त निर्देशिकाओं के बाहर कुछ भी नहीं |
| **Network** | डिफ़ॉल्ट रूप से केवल `localhost:11434` पर HTTP — शून्य बाहरी आउटगोइंग। केवल तभी रिमोट जब `OLLAMA_HOST` कहीं और इंगित करता है |
| **Secrets** | `OLLAMA_API_KEY`, यदि सेट किया गया है, तो पर्यावरण से पढ़ा जाता है और केवल एक गैर-लूपबैक `OLLAMA_HOST` पर एक बियरर टोकन के रूप में भेजा जाता है; कभी भी डिस्क पर नहीं लिखा जाता है या लॉग नहीं किया जाता है |
| **Telemetry** | कोई भी एकत्र या भेजा नहीं गया |
